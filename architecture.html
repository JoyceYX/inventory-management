Inventory Management System — Architecture

A full-stack factory inventory demo: a Vue 3 single-page app talking to a FastAPI backend that serves data filtered in-memory from static JSON files. No database — every restart reloads from disk.

Vue 3 + Vite FastAPI + Pydantic In-memory JSON store No database

1System Architecture

Client

Vue 3 SPA · localhost:3000 (Vite)
  • views/*.vue — Dashboard, Inventory, Orders, Demand, Spending, Reports, Backlog
  • components/FilterBar.vue — global filter UI
  • composables/useFilters.js — shared filter state
  • api.js — axios client, one function per endpoint
→

API Server

FastAPI · localhost:8001 (uvicorn)
  • main.py — all routes + Pydantic models in one file
  • apply_filters() — warehouse / category / status
  • filter_by_month() — month or quarter strings
  • CORS: allow_origins=["*"] (dev-only)
→

Data Layer

In-memory · loaded at import time
  • mock_data.py — reads JSON into Python lists
  • data/inventory.json, orders.json, etc.
  • No cache, no persistence — restart re-reads files

3Data Flow — Example: Filtering Inventory by Warehouse

User selects a warehouse
FilterBar.vue — a <select v-model="selectedLocation">
Shared state updates
selectedLocation is a module-level ref in useFilters.js, shared by every component that calls useFilters()
View reacts
Inventory.vue has watch([selectedLocation, selectedCategory], loadInventory)
API call fires
api.getInventory({ warehouse, category }) in api.js builds query params and calls axios
HTTP request
GET /api/inventory?warehouse=...&category=...
Server filters in-memory
apply_filters(inventory_items, warehouse, category) filters the list loaded from inventory.json
Response validated
FastAPI serializes the result against response_model=List[InventoryItem]
Vue renders
Result lands in the items ref; the filteredItems computed applies local search/sort, and v-for="item in filteredItems" renders the table

4Global Filter System

Time Period Warehouse Category Order Status

All 4 filters are defined once as singleton refs in useFilters.js and rendered by a single FilterBar mounted globally in App.vue, above <router-view/> — so one filter bar affects every page. Each view independently watches the filters it cares down and re-fetches; there is no central dispatcher.

!Known Gaps

Found during investigation — not wired up end-to-end

  • client/src/api.js calls /api/tasks* and /api/purchase-orders* endpoints that do not exist in server/main.py. These requests 404; App.vue catches the errors silently and falls back to a hardcoded mock task list in useAuth.js.
  • Dashboard.vue's template references a <PurchaseOrderModal> component that is never imported or registered — and no PurchaseOrderModal.vue file exists in components/. The purchase-order creation flow from the Backlog view is incomplete.
